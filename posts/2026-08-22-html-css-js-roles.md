클로드 코드와 함께 이 블로그를 만들면서, HTML·CSS·JavaScript가 각각 어떤 역할을 맡고 있는지 다시 한번 정리해봤습니다. 프레임워크 없이 순수하게 세 가지만으로 동작하는 사이트를 만들다 보니 각 언어의 경계가 오히려 더 선명하게 보였습니다.

## HTML — 뼈대와 의미

HTML은 페이지에 **무엇이 있는지**를 정의합니다. 이 블로그의 `index.html`은 글 목록이 들어갈 자리(`#post-list`)만 표시해두고, `post.html`은 글 제목과 본문이 들어갈 자리(`#post-content`)만 표시해둡니다. 실제 내용은 비어 있는 상태로 시작해서, 나중에 JavaScript가 채워 넣는 구조입니다.

`<header>`, `<main>`, `<article>` 같은 시맨틱 태그를 쓰면 브라우저와 스크린리더가 페이지 구조를 이해하기 쉬워진다는 것도 새로 알게 됐습니다. `<div>`만 잔뜩 써도 화면에는 똑같이 보이지만, 의미는 완전히 다릅니다.

## CSS — 스타일과 상태

CSS는 **어떻게 보이는지**를 정의합니다. 이 블로그에서 가장 인상 깊었던 부분은 색상을 CSS 커스텀 프로퍼티(`--color-bg`, `--color-text` 등)로 미리 선언해두고, 라이트/다크 모드에 따라 값만 바꿔치기하는 방식이었습니다.

```css
:root[data-theme="dark"] {
  --color-bg: #121212;
  --color-text: #e8e8e8;
}
```

이렇게 해두면 실제 스타일 규칙(`body { background: var(--color-bg); }`)은 단 한 번만 작성하면 되고, 테마 전환은 이 변수 값만 바뀌는 문제로 단순해집니다. `color-scheme: light dark` 같은 속성이 스크롤바 같은 브라우저 기본 UI 색상까지 테마에 맞춰준다는 것도 이번에 처음 알았습니다.

## JavaScript — 동작과 데이터

JavaScript는 **무엇을 하는지**를 담당합니다. 이 블로그에서 JS가 하는 일은 크게 세 가지였습니다.

1. `posts.json`을 `fetch`로 불러와 글 목록을 렌더링하기
2. 마크다운 파일을 `fetch`로 불러와 직접 만든 파서로 HTML로 변환하기
3. `localStorage`에 테마 설정을 저장하고, 클릭 이벤트로 다크모드를 토글하기

특히 마크다운 파서를 직접 만들면서, 인라인 코드 문법을 정규식으로 처리할 때 순서가 중요하다는 걸 배웠습니다. 코드 스팬을 먼저 분리해두지 않으면 코드 안에 있는 `*` 기호가 강조(굵게/기울임) 규칙에 잘못 걸릴 수 있기 때문입니다.

## 세 가지가 만나는 지점

> 결국 HTML은 그릇, CSS는 그릇의 모양과 색깔, JavaScript는 그 그릇에 무엇을 담을지 결정하는 역할이라는 비유가 가장 와닿았습니다.

빌드 도구 없이 이 세 가지만으로도 다크모드, 반응형 레이아웃, 마크다운 렌더링까지 다 구현할 수 있다는 걸 직접 확인한 게 오늘 가장 크게 배운 점입니다.
