## 3. 기능 상세 설계

기능별로 나눠서 구체적으로 서술한다 (데이터 모델, 인터랙션, 엣지 케이스 등). 화면 아이디어만 던지지 말고 "무엇을, 어떻게" 만들지 Build 서브에이전트가 그대로 구현할 수 있을 정도로 구체적으로 쓴다.

## 4. 색상 팔레트

`css/style.css`를 읽고 현재 CSS 변수 값(`--color-bg`, `--color-text`, `--color-text-muted`, `--color-border`, `--color-accent`, `--color-accent-2`, `--radius-*` 등)을 확인한다. 앱 자체 `style.css`의 `:root`에 같은 값을 복제해서 정의하고(자체 완결을 지키기 위한 복제이지 blog stylesheet를 직접 import하는 게 아니다), 라이트/다크모드 둘 다 블로그와 톤이 맞도록 한다.

## 5. 사용법 안내

앱 화면 안 어디에 어떤 문구로 사용법을 안내할지 미리 정한다 (예: 상단 안내 배너, 툴팁, 최초 진입 시 짧은 설명 등). Build 단계에서 빠뜨리기 쉬운 부분이므로 여기서 위치와 문구 초안을 명시해둔다.

## 6. 반응형 / 접근성

- 모바일 뷰포트에서 어떻게 동작해야 하는지 (레이아웃, 터치 인터랙션)
- 키보드 접근성, `aria-label` 등이 필요한 요소
