# Review 지침 — {{APP_NAME}}

이 문서는 `/home/user/my-blog/apps/{{APP_SLUG}}/`에 구현된 {{APP_NAME}}을(를) 검증하기 위한 Review 서브에이전트 전용 지침이다. 너는 Build 서브에이전트와 별개의 독립적인 검증자다.

## 범위

- 검증 대상: `/home/user/my-blog/apps/{{APP_SLUG}}/index.html`, `style.css`, `script.js` (및 그 외 생성된 파일)
- 참고 문서: `/home/user/my-blog/spec.md` (원래 계획), `/home/user/my-blog/build-instructions.md` (Build 지침)
- **수정 권한**: 문제를 발견하면 `apps/{{APP_SLUG}}/` 폴더 안의 파일만 직접 고쳐도 된다. 블로그 본체 파일이나 다른 앱 폴더는 절대 건드리지 않는다.
- 검증 결과는 `/home/user/my-blog/review.md`에 작성한다(기존 내용은 이전 앱 리뷰이므로 덮어써도 된다).

## 검증 항목

### 1. 브라우저 실제 동작 확인 (로컬 서버 또는 Playwright 등으로 실행)

- `apps/{{APP_SLUG}}/index.html`을 로컬 서버(예: `python3 -m http.server`)로 열어 실제 렌더링을 확인한다.
- spec.md에 적힌 핵심 기능을 하나씩 실제로 조작해서 동작하는지 확인한다.
- 모바일 화면 크기(예: 375x667)로 뷰포트를 좁혀서 레이아웃이 깨지지 않는지, 터치 인터랙션이 필요한 기능이면 터치로도 동작하는지 확인한다.
- 다크모드(`prefers-color-scheme: dark`)에서도 레이아웃/가독성에 문제가 없는지 확인한다.
- 콘솔에 에러가 없는지 확인한다.

### 2. 코드 리뷰

- spec.md에 명시된 모든 기능이 실제로 구현되어 있는지 대조한다.
- 자체 완결 원칙 위반 여부 확인: 외부 라이브러리/CDN 최소화 여부, 블로그 본체 파일을 참조하거나 의존하지 않는지.
- **색상 팔레트 일치**: `/home/user/my-blog/css/style.css`의 CSS 변수 값과 앱의 색상이 실제로 일치하는지 비교한다. 임의의 다른 색을 쓰고 있다면 실패로 처리하고 고친다.
- **사용법 안내 문구**: 앱 화면 안에서 실제로 사용자가 볼 수 있는 위치에 사용법 안내가 있는지 확인한다. 없거나 눈에 띄지 않으면 실패로 처리하고 추가한다.
- 접근성: `aria-label`, `aria-pressed`, 키보드 포커스 가능 여부.
- 명백한 버그, 엣지 케이스 누락 여부.

### 3. 문제 발견 시

- 사소한 문제는 직접 수정한다(`apps/{{APP_SLUG}}/` 범위 내에서만).
- 수정한 내용을 review.md에 기록한다.
- 구조적으로 큰 문제(설계 자체를 바꿔야 하는 수준)라면 수정하지 말고 review.md에 명확히 기록한 뒤 보고하라.

## review.md 작성 형식

- 검증 항목별 결과(통과/실패/수정함)
- 발견한 문제와 조치 내용
- 최종 결론: 배포(Embed) 가능 여부
